# 肉の田島 ギフトEC 構成案（ドラフト v0.2）

2026-10-20 時点のヒアリング結果（2回目まで）をもとにした叩き台。アプリの料金・仕様はWeb上の情報ベースで、未確認のものは「要確認」と書いている。

## 1. 決まったこと

| 項目 | 決定内容 |
|---|---|
| 位置づけ | 既存の自社EC（Shopify以外のカート）は残し、**ギフト専用サイトを別に新設** |
| ブランド | 「肉の田島」名義のまま、和モダン・高級寄せのトーン |
| カート | **Shopify**（ベーシックプラン想定） |
| 売り方 | ① 配送ギフト（のし付き） ② ソーシャルギフト（**受け取った人が選べる**タイプ） |

| 温度帯 | 冷凍＋冷蔵。**混在注文は箱を分けて発送、送料は2口** |
| 送料 | 送料別（地域×温度帯） |
| お届け日の指定 | 注文から30日先まで |
| 価格帯 | 5,000〜10,000円、10,000〜30,000円 が中心 |
| 決済 | クレカ＋Apple Pay/Google Pay、Amazon Pay、PayPay、銀行振込 |

| 出荷 | 東京都から自社出荷・ヤマト クール便（B2クラウド）。正午12時締めで次の出荷日に発送（§5） |
| 規模 | ピーク月 100〜500件（配送先ベース） |
| 制作 | 公式テーマをベースに、このリポジトリでLiquidを書いて作り込む |
| リピート施策 | 送り先の住所録、季節のリマインドメール、LINE連携 |
| 領収書 | 希望者のみ手動で発行 |

| ソーシャルギフトの受取期限 | 30日。期限切れは購入者に連絡し、購入者の住所に発送 |
| 時期 | 期限なし |

## 3. 機能ごとの実現方法

| 要件 | 実現方法 | 月額の目安 | 備考 |
|---|---|---|---|
| のし（表書き・名入れ・内/外） | ギフトアプリ or テーマ自作（商品の追加入力項目） | 0〜 | 複数配送先と組み合わせる場合は**配送先ごとにのしを選べる**ことが必須 → アプリ側で対応させる |
| 1注文で複数のお届け先 | アプリ必須（Shopify標準は1注文1配送先） | アプリ代 | 親注文と子注文に分かれる方式が多い。売上が二重に計上されないか要確認 |
| 配達日時指定 | 配送日時指定アプリ | $9.80〜 | 休業日、締め時刻、年末の指定不可期間、ヤマトの時間帯に対応しているもの |
| 冷凍・冷蔵の分割発送 | **Shopify標準の配送プロファイル**を2つ作る | 0 | 混在時は送料が自動で合算＝2口になる。希望どおりの動きを標準機能で実現できる |
| 納品書の金額非表示 | 納品書テンプレート（Liquid）を編集 | 0 | のし情報と温度帯も印字する |
| ソーシャルギフト（選べる） | ギフトアプリのカタログ機能 | アプリ代 | **予算を一番圧迫する項目**。§6参照 |
| 住所録 | Shopify標準の顧客アカウント（複数住所を登録） | 0 | 複数配送アプリが住所録を呼び出せるかは要確認 |
| 季節のリマインドメール | Shopify Email＋Flow（購入者に「お歳暮2026」などのタグを付けて翌年に配信） | 無料枠あり | |
| LINE連携 | CRM PLUS on LINE（Freeプランあり） | $0〜 | LINE通知メッセージは2026年6月からの新プランで1通5円の従量課金（従業員数などの条件あり） |
| B2クラウド連携 | 配送日時アプリのCSV出力 or B2用CSVアプリ | 0〜 | クール区分（冷凍/冷蔵）が分かれて出力されること、ご依頼主＝贈り主になること |
| 決済 | Shopifyペイメント（クレカ・Apple/Google Pay）、Amazon Pay、銀行振込（手動決済） | 決済手数料のみ | **PayPayはShopifyペイメント単体では使えず**、KOMOJU等の決済代行が必要。その場合Shopify側に追加手数料がかかる |

### ギフト機能はなるべく1アプリにまとめる

のし・複数配送先・配送先ごとの日時・eギフトを別々のアプリで足すと、注文データの持ち方がアプリごとに違い、組み合わせると崩れやすい（例：複数配送アプリで分けた配送先に、別アプリで入力した日時が引き継がれない）。

候補は国産の **All in gift**（のし、複数配送先、eギフト、カタログギフトに対応と案内されている）。料金は2025年7月に改定されており、現行の金額は**要確認**。14日間の無料体験あり。

## 4. 月額コスト試算（予算2万円に対して）

$1＝150円で換算した目安。

| 項目 | 月額 |
|---|---|
| Shopify ベーシック（年払い） | 3,650円（月払いなら4,850円） |
| 配送日時指定アプリ | 約1,500円〜 |
| LINE連携（Freeプラン） | 0円（＋通知1通5円） |
| Shopify Email／Flow | 0円（無料枠内） |
| **小計** | **約5,150円** |
| ギフトアプリ | **残り約14,800円以内に収めたい** |

参考：機能ごとに別アプリで揃えた場合

- 複数配送先アプリ（複数配送先.amp）：$29〜（約4,400円）
- eギフトアプリ（MakeGift）：$49（約7,400円）＋eギフト売上の3%
- → 合計 約17,000円＋手数料で予算内には収まるが、**MakeGiftは住所を入力してもらう方式で、受け取った人が商品を選ぶ機能は確認できなかった**

**結論：** 「受け取った人が選べる」を予算内で実現できるかは、All in gift の現行料金と、カタログ機能の中身しだい。次の作業はこれを開発ストアで確かめること。

**予算に収まらなかった場合：** 選べるギフトは後回しにして、まずは贈り主が選んだ商品をそのまま送るソーシャルギフトで始める。

## 5. 配送ルール

### 温度帯
- 配送プロファイル「冷凍」「冷蔵」を作り、全商品をどちらかに割り当てる
- 送料は別にもらう。ヤマト クール便の東京発・地域別料金で設定（冷凍・冷蔵それぞれ）
- クール便は箱のサイズで料金が変わるので、商品の重量を箱のサイズに対応させて設定する
- 混在注文は送料が2口分自動で加算される。出荷時は送り状も2枚（クール冷凍とクール冷蔵）

### 出荷カレンダーとお届け日

作業できる曜日：

| 作業 | 月〜金 | 土 | 日 |
|---|---|---|---|
| 注文確認・送り状発行（事務所） | ○ | × | × |
| 商品の用意・梱包・発送 | ○ | ○ | × |

締め時刻は正午12時。注文が入った日時ごとの出荷日：

| 注文が入った日時 | 出荷日 |
|---|---|
| 月 0:00〜12:00 | 火 |
| 月 12:00〜火 12:00 | 水 |
| 火 12:00〜水 12:00 | 木 |
| 水 12:00〜木 12:00 | 金 |
| 木 12:00〜金 12:00 | 土（送り状は金曜に発行） |
| 金 12:00〜日 24:00 | 月（月曜の午前に確認・送り状発行をして、その日に発送） |

- 配送日時アプリでは「出荷できる曜日：月〜土」「最短の出荷：1出荷日後」「締め時刻：12時」と設定すれば、上の表と同じ結果になるはず。土曜の午後に入った注文が火曜にずれず月曜出荷になるかは、検証で確かめる
- 月曜は週末の注文の処理が午前に集中する。ピーク時は月曜午前の人手を厚くする
- 最短お届け日 ＝ 出荷日 ＋ ヤマトの東京発・地域別お届け日数
- お届け日は**注文から30日先まで**指定できる（冷蔵。冷凍も30日で仮置き）
- 年末の指定不可期間（例：12/30〜1/3）とお歳暮の受付締切日を、アプリの休業日設定に入れる
- 銀行振込の注文は入金を確認してから出荷する。入金確認は平日だけなので、振込の場合は最短お届け日を後ろにずらす（例：注文から5日後以降）

### のし・メッセージ
- 表書き：御歳暮／御中元／内祝／御祝／御礼／寸志／無地 など
- 名入れ：自由入力（文字数上限あり）
- 内のし／外のし：配送ギフトは内のしをおすすめとして初期選択にする
- メッセージカード：今回は必須機能から外れたが、ギフトアプリに含まれていれば使う

### 納品書・送り状
- 納品書：金額は出さず、のし情報、温度帯、贈り主の名前を印字する
- 送り状のご依頼主：**贈り主（購入者）の名前**。お店の名前にはしない（受け取った人が誰からの贈り物か分かるように）

## 6. ソーシャルギフト（選べるギフト）の仕様

| 項目 | 案 |
|---|---|
| 売り方 | 「田島の選べる肉ギフト 5,000円コース／10,000円コース／20,000円コース」のように**価格帯ごとのコース商品**として販売。予算に収まらなければ、まず贈り主が選んだ商品をそのまま送る方式で始め、コースは後から足す |
| 贈り方 | 購入後に受取URLが発行され、LINEやメールで相手に送る |
| 受け取った人 | コース内の商品から1つ選ぶ → 住所とお届け日を入力 |
| 送料 | 通常の注文は送料別だが、eギフトは購入時に相手の住所が分からない。全国一律の送料を購入時に足すか、送料込みの価格にするかは要決定 |
| 冷蔵品 | 選んだ時点から最短お届け日を計算する（通常の配送ギフトと同じルール） |
| 受取期限 | 購入から30日。期限が切れたら購入者に連絡して、購入者の住所に発送する（選べるコースの場合は、購入者に商品を選んでもらう） |
| のし | eギフトはのしなし（メッセージカードのみ）にするのが一般的。要決定 |

## 9. 毎日の受注〜出荷の流れ（想定）

1. 朝：「今日が出荷日」の注文を抽出する（お届け日から逆算した出荷予定日で絞り込む）
2. B2クラウド用CSVを出力（クール区分ごと、ご依頼主＝贈り主）
3. B2クラウドに取り込み → 送り状を発行
4. 納品書（金額なし・のし情報入り）を印刷 → のしを付けて梱包
5. 追跡番号CSVをShopifyに取り込む → 発送完了をメール（＋LINE）で通知

ピーク時の500件／月なら1日あたり20〜30件程度。半自動（CSVの出力と取込）で回せる量。
**要確認：** 日時指定アプリで「出荷予定日」による絞り込みができるか。できなければFlowでタグを付けて代わりにする。

## 10. 落とし穴（先に潰しておく）

1. **ベーシックプランではチェックアウト画面を編集できない**
   → のし・お届け日時は、商品ページかカートで入力してもらう必要がある
2. **すぐに決済できるボタン（Apple Pay／Amazon Pay／今すぐ購入）はカートを飛ばす**
   → のし・日時が未入力のまま注文できてしまう。商品ページではこれらのボタンを非表示にし、カートでは必須項目を入力するまで押せないようにする
3. **複数配送先アプリの親注文・子注文**
   → 売上レポートが二重にならないか、B2用CSVに出るのが子注文だけか確認
4. **ソーシャルギフトの受け取り待ちの在庫**
   → 受け取った人が選ぶまで商品が決まらないので、コース全体で販売上限を管理する
5. **PayPayを入れると手数料が上がる**
   → Shopifyペイメント以外の決済代行を使うと、Shopify側の追加手数料がかかる。オープン時は入れず、反応を見てから追加でも良い

## 13. アプリ検証チェックリスト（フェーズ0）

- [ ] 1注文で複数の配送先に分けられ、**配送先ごとに** のし・お届け日・時間帯を指定できる
- [ ] 冷凍と冷蔵が混在したとき、配送先ごとに送料が2口で計算される
- [ ] 出荷曜日（月〜土）・締め時刻（12時）・年末の指定不可期間を設定でき、§5の表どおりの出荷日になる（特に金曜午後・土曜午後・日曜の注文）
- [ ] お届け日の指定を30日先までに制限できる
- [ ] 銀行振込のときだけ最短お届け日を後ろにずらせる
- [ ] eギフトの受取期限を30日にでき、期限切れを購入者に知らせられる
- [ ] B2クラウド用CSVにクール区分、お届け日時、ご依頼主＝贈り主が正しく出る
- [ ] 納品書にのし情報が出る（アプリのデータを納品書テンプレートから読める）
- [ ] eギフトで受け取った人がコース内の商品を選べる。選んだ後の注文が通常の注文と同じ流れで出荷できる
- [ ] 親注文・子注文で売上が二重に計上されない
- [ ] Amazon Pay・Apple Payで決済しても、のし・日時の情報が消えない
- [ ] 合計の月額が2万円以内

## 14. まだ決めていないこと

1. 祝日の扱い（事務所は休みか、梱包・発送はするか）
2. ソーシャルギフトの送料（全国一律で購入時に足す or 送料込みの価格）
3. 箱のサイズと、商品ごとにどのサイズで送るか（送料の計算に使う）
4. 冷凍品のお届け日指定の上限（いまは冷蔵と同じ30日で仮置き）
5. ドメイン（既存ドメインのサブドメイン or 新しいドメイン）
6. 立ち上げ時の商品数（SKU）
